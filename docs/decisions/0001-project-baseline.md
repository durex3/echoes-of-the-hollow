# ADR 0001：小型 2D 工程基线

状态：采用。日期：2026-09-25（本机工作日期）。

## 背景

用户已有横版像素素材和 Godot 4.7.2，希望直接在桌面建立规范、可学习、可持续迭代的工程。

## 决定

1. 固定 Godot 4.7.2 + GDScript + Compatibility，Windows 首先验证。
2. features 按功能分目录，原生文本场景与资源，不添加外部运行框架。
3. 小状态机、节点组件和父级接线。两项 Autoload 足够，不引入万能事件总线。
4. M1 只做两个房间的双跳回溯闭环，延后 Boss 和大型地图。
5. 原生 SceneTree 测试运行器，避免首版引入测试插件依赖。
6. 自动测试、可视检查、人工手感验收分别记录，不把任何一个当作另两个的替代。
7. 资源预处理脚本仅首次生成；保存下来的房间是编辑器可继续维护的权威内容。

## 后果

优点：用户可直接导入、编辑、运行；少依赖；行为可回归；脚本职责可解释。
代价：当前 UI 由代码构造；没有复杂测试发现/覆盖率工具；动画帧索引还需官方帧表复核。
如内容数量/测试规模增长，再单独写 ADR 评估 UI 场景化、测试框架和资源加载策略。
