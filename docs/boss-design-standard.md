# Boss 设计与实现规范

本项目的 Boss 采用“房间编排器 + 决策器 + 独立攻击状态”的结构。Boss 本体负责移动、受伤、死亡和状态执行；不把房间锁门、镜头、音乐、奖励、存档和所有技能选择揉进同一个脚本。

第三关重构参考 `ColeW96/metroidvania-forge-tutorial` 的 Boss 组织方式和 Nega Pink Box 的技能节奏。该仓库代码采用 MIT License；本项目只移植机制和时序，视觉继续使用本项目已登记素材，不直接复制来源不明的图片资源。

## 房间编排器

Boss 房进入触发区后才开始战斗。编排器负责：

- 锁定 Boss 房真实边界和镜头范围；
- 关闭战斗前不可用的门，战斗结束后开启正确出口；
- 启用 Boss 房平台或 TileMapLayer；
- 显示和更新 Boss 血条；
- 切换战斗音乐与战后音乐；
- 监听 Boss 击败，发放奖励并保存稳定完成标记。

Boss 本体不得直接依赖跨场景绝对路径完成这些流程。子场景通过信号向上报告 `awakened`、`defeated` 和伤害事件。

## 决策器

决策器只回答“下一招是什么”，不直接操作伤害节点。选择依据包括：

- 玩家与 Boss 的距离和相对高度；
- 玩家是否在地面、空中或墙边；
- 上一次攻击，避免同一招无限重复；
- 每个技能自己的冷却；
- Boss 当前生命，但不通过阶段转场改变基本规则；
- 当前场上是否已经有分身、锚点或其他持续威胁。

单循环的基本顺序是：追击 → 选择攻击 → 蓄力 → 生效 → 收招 → 冷却 → 再次选择。技能有就放，但必须满足冷却、距离和场上数量限制。

## 独立攻击状态

每个技能独立管理自己的：

- 蓄力动画和视觉预警；
- 物理位移；
- Hitbox/Hurtbox 生效窗口；
- 音效、屏幕反馈和粒子；
- 收招与反击窗口；
- 冷却计时。

三关统一使用 `BossStateMachine` 管理当前攻击状态，使用各自的 `Decision` 类选择状态。Boss 主脚本只保留目标、移动、生命和信号；技能状态不得直接互相修改另一个技能的计时器。

攻击状态执行期间暂时禁止决策器抢招。伤害时钟必须与动画和可见危险段一致；同一次攻击对同一个 Hurtbox 去重，下一次独立攻击恢复判定。

## 三关 Boss 的独立打法

### 第一关：空谷守门者

核心是本体近战与七把独立追踪飞剑的并行压力。飞剑庭出现后，Boss 本体仍可自由移动和出招；冲刺是躲避剑阵和调整位置的主要手段。飞剑必须有独立生命期、碰撞和目标选择，不能只是 Boss 的装饰特效。

### 第二关：炉心监守者

核心是高空蓄力、落点判断和横向火墙。蓄力阶段必须持续保持高压姿势并明显闪红；落地后焰浪贯穿可见地面段。护盾可以挡住关键火墙，但不能替代玩家判断落点和起跳时机。

### 第三关：缚钟守望者

核心是快速镰击、锚点追猎和持续钟影分身。取消一二三阶段转场，所有技能在同一循环中由决策器按距离、高度、冷却和场上威胁选择。分身必须独立造成真实伤害，并提供可读的地面/高位节拍；锚点必须在可见位置周期脉冲；低血量只触发一次终结技，不改变 Boss 的基本 AI。

## 验收标准

- 站在 Boss 身边持续顶撞会按独立接触脉冲及时受伤；
- 普通攻击预警短而清楚，收招后存在可利用反击窗口；
- 每个持续威胁都能通过真实 Hurtbox 造成伤害；
- 技能不会因阶段计数、旧状态或同一帧重复调用而失效；
- Boss 移动使用完整动作帧，攻击动画、危险范围和物理节点同步；
- 三关的核心应对方式不同，不用堆血量或重复同一招制造难度；
- 必须同时通过组件测试、章节路线检查、视觉检查和真人输入验收。
