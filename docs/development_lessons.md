# 第一、二关开发经验与防回归规则

整理日期：2026-09-27。依据第一、二关的用户反馈、实际实现和[验证记录](verification.md)，用于后续开发、排错及评审。当前玩法约定在[AGENTS.md](../AGENTS.md)，数值以Resource和[动画映射](animation-map.md)为准；本文不把当前招式或数值强加给所有后续章节。

## 1. 先复现表现，再找责任环节

“模糊”“动作不对”“碰到了不扣血”“门对不上”要分别定位。记录房间、动作阶段、朝向、位置、可见特效和实际HP变化。参考视频先拆解准备、持续蓄力、释放、危险持续和收招，不能只复制最亮的一张截图。

按源图/选帧、渲染、玩法计时、碰撞、房间/镜头、UI的顺序排查，只改有证据的环节。反馈角色太小时，不同时更改镜头、碰撞和地图。已获认可的主角动作、输入语义和稳定场景引用应保留；用户后续明确变更时再同步更新实现与规则。

## 2. 像素清晰度看完整渲染链路

两个Boss已用最近邻，粉色Boss蓄力仍显糊，说明项目默认过滤并非唯一原因。本轮还发现红色染色抹平暗线、光晕过宽遮住身体。

排查顺序：原PNG与帧选区 → 项目默认过滤 → 精灵节点覆盖 → shader采样与光晕/残影 → 无损导入、mipmap → 最终显示倍率。项目设置和CanvasItem的枚举数字含义不同，应核对实际枚举名称，不能只比较数字。

有效倍率为精灵×镜头×窗口。当前Boss和新骑士用10/7×1.4=2倍内部像素，默认窗口再放大2倍；局部精灵倍率非整数并不直接等于错误。当前视口800×450、默认窗口1600×900，整数缩放可留边。Boss激活前后不能突然缩放人物。

分别查看待机、攻击、蓄力峰值和移动残影。最亮时仍须看清轮廓和盔甲层次；不要用大光晕遮问题，也不要把低分辨率原图缺少的细节误判成过滤错误。

## 3. 换素材要交付整套动作

候选素材同时检查剪影、可见身高、配色、像素密度、武器和动作完整度，不能只因名称含“骑士”就使用。第一关Boss、第二关骑士小怪和粉色Boss应有独立身份，各章不靠同一敌人换色或加血量区分。

先看完整动作接触表，再接原生SpriteFrames；记录格子尺寸、序号、朝向、脚底、准备/生效/收招及死亡末姿。新骑士140px的画布不等于140px可见身高。排除空白格和不合用途的烘焙大光片，视觉层修正透明边距或跑步躯干偏置，不逐帧重裁中心造成滑脚，更不能移动碰撞去追贴图。

资产复制不改原文件，登记来源URL、相对路径、SHA-256和原许可。用户已授权的外部角色/特效可以使用，但CC0包的许可不能覆盖授权待核对的课程素材。工具只更新指定角色，不重建已经审核的全部帧表、UID或手工地图。最终放回真实背景，对比主角、普通怪和Boss的比例。

## 4. 输入、动画和伤害使用同一时序

主角左右手交替的确定含义：一次新按键只打一手，下一次新按键换另一手，长按不自动连击。不能为了衔接动画擅自增加第二次攻击。续招缓冲只保留一次，受伤、死亡、切房、菜单重置时清空。

玩法阶段统一驱动准备、生效、收招与动画速度，刀光不另启独立时钟。真实生效阶段才有攻击伤害；被打断立即关掉原攻击。检查两种朝向、持续按键、新按键交替以及末姿衔接。

Boss蓄力需要持续姿势、约定的全身闪红和释放动作；悬停加光圈不等于完成蓄力表现。保留自然动作和音效预警，移除招式名称、躲避建议、收招建议等HUD文字，不绘制未来攻击轨迹或攻击距离。已经发生的挥斩和危险特效仍应清楚可见。

## 5. 实体阻挡、伤害与特效必须分别验证

实体碰撞只能防穿过，不会自动造成伤害。全游戏每类敌人的身体接触都要通过Hitbox/Hurtbox/Health真实扣血，不能只验证第一关Boss。火墙等效果必须测试地面、高台、边缘、持续重叠和消散后的残留，避免“站上面不掉血”。视觉光晕不参与碰撞，只有危险阶段有伤害。

一次扑咬的身体与咬击、一次下砸的爆发与左右火墙、同轮副剑，分别按约定共享去重。护盾挡住一次攻击后不能被其另一个形状补伤；下一次独立攻击仍危险。不要用全局长无敌掩盖去重问题。

高速弹体检查初始重叠和整段运动扫掠，测试薄墙、高速穿越，墙体优先阻挡。暂停冻结时钟，死亡、换房与重试清理旧弹体/残影；同步死亡回调后不能重新启用已经结束的伤害。

## 6. Boss特色来自决策与节奏

第一关为地面国王与王之剑庭，第二关为粉色骑士的高空持续蓄力和落地焰浪。参考第二关的完成质量，不等于给第一关复制相同的升空大招。

当前剑庭召唤时无敌，结束立即解除保护并恢复普通追击和出招；飞剑独立运行。发射轮次和结束事件不能覆盖本体近战动画、重置本体状态或强制收招，不允许剑阵重叠。追踪需要转向速度和寿命上限，保留跑跳、转向及地形阻挡的应对空间。

AI至少验证近身、远处、贴墙、跨到背后、连续重复招式、半血和大招/普攻并行。难度提升来自组合与决策，不能靠缩掉全部预警、收招、无限追踪或堆血量。

## 7. 房间、门与地图使用一致的空间规则

两个Boss房固定单屏，真实边界同时保证角色不能走出可见画面。只锁门会漏掉左右逃离，只画封闭柱或罩层不是可靠碰撞。验证入场、战斗、胜利、死亡重试和旧通关档；开战前后不改镜头倍率。

当前第一关从左门进入，胜利后开放左返回门和右章节门；第二关胜利前不能往左逃，胜利后左侧可步行返回、右侧开放章节出口。早期“中间出现门”等方案已经被后续反馈调整，不应恢复为当前规则。

每个门核对房间ID、出生点、左右方向、显示名称、地图连线和HUD下一目标。双向门要两端实走，单向捷径不得画成双向连接。减少重复教学牌，用可辨认地标辅助地图；提示不得遮住敌人、通路或落脚点。

## 8. 存档和回血分开处理

存档点和Boss入口自动保存只更新检查点、保存进度，正常、重复或失败均不改变当前HP，文案只写“保存进度”。死亡复活、生命升级、封印或Boss胜利的独立回血仍保留，不能因为它们也保存就一并删除奖励。

当前不持久化瞬时HP，继续游戏和死亡复活保持原恢复规则。“保存时不加血”不能擅自扩展为新存档格式。保存变更要验证失败提示、会话收益、备份、旧档和跨进程读取；测试文件与玩家文件始终隔离。

## 9. 分层验收，不用数量替代证据

| 验证层 | 能证明什么 | 不能替代什么 |
|---|---|---|
| 组件/机制场景 | 真实命中、阶段、护盾、清理及边界 | 整章通关和难度 |
| 连续InputMap路线 | 两种支路顺序、门、奖励、存档可连续完成 | 真人首次读招、认路及手感 |
| 实际渲染截图 | 帧选区、比例、遮挡、可见危险和提示 | 所有帧的动态衔接、听感、实体设备 |
| 用户试玩 | 对实际试玩版本和具体问题的反馈 | 未测试设备、其他版本或正式导出包 |

取消存档回血后，旧路线暴露边挥剑边撞怪、依赖祭坛补血的问题。查看每次伤害的来源、位置和状态，修正自动脚本的正常走位；不能回退用户规则、关闭碰撞、注入HP或削弱敌人来制造通过。

组件测试允许隔离摆位，但必须注明。连续路线只用正常输入，不传送、不加无敌、不直接写通关标记；允许读取状态辅助决策，报告时说明并不等于真人难度。截图保存断言不算新增行为覆盖。

行为变更执行tools/check.ps1；共享战斗、存档、门与章节流程执行-Full；视觉变更加-Visual并打开受影响截图。记录首个失败、修复原因和最终完整命令结果；只有文档变化不重复已通过的整套游戏测试。

## 10. 日常执行和提交

按问题选skill：素材用create-game-assets，动画用godot-animation，碰撞用godot-physics，AI用game-ai，地图/镜头用level-design或camera-systems。使用其方法，不为套用skill增加无关框架；实际引擎版本与运行结果优先于示例默认值。

评审顺序：用户最新约定 → 范围 → 来源/配置 → 真实行为 → 实际画面 → 文档与遗留项。具体实现见[架构](architecture.md)、[美术规范](art_direction.md)、[章节递进](level_progression.md)和[测试规范](testing.md)，历史结果留在验证记录中，不在多处维护矛盾副本。

提交源码、原生场景、已登记的必要素材及许可、.uid/.import、测试和说明；排除.godot、Python缓存、下载原包、截图、日志、导出包和个人存档。同步制作工具的生成配方，不重新生成覆盖手工地图。
