## 已完成与边界

第一、二关主线仍由 `app/main.tscn` 启动。第三关目前是 **5 个原生房间的独立前半段试玩**：风蚀阶庭、守钟外廊、断钟中庭、回音修院、悬铃回廊。壁跃能力与教学、鸣石、法师与铃翼技能、美术反馈、三章小怪 AI 和抗连续硬直已实现；法师贴身反击已通过真实扣血回归。

试玩入口为 `features/world/prototypes/bell_court_preview.tscn`。默认 6HP，具备二段跳、冲刺和护盾；踏壁在试玩中领取。另有 5HP 无盾的基线检查。试玩进度只在内存中，不写主线存档。

**尚未完成：**完整双支路及承重回桥、钟庭之心、合鸣桥廊、缚钟守望者 Boss、第三关正式章节入口/地图/存档/结局。五房间试玩不是完整第三关；第三关整体难度高于第二关仍是后半章与终局要验证的目标。

## 下一项实际开发：双支路和真实回桥

Mac 上首先完成现有工程导入、试玩和检查入口适配，再开始内容任务。第一项内容任务是 **承钟机室与东西承重回桥闭环**，沿用现有五房间，不重建已手工调整的地图，也不重做已认可的小怪或壁跃操作。

1. 阅读现有原生地图、门和出生点，以及第三关移动测量记录。沿用实测的可达范围；新组合跳跃必须先隔离测量再定平台。
2. 新增承钟机室；先到宽台战斗，后把单个法师与已学鸣石组合。悬铃回廊保留已有单怪教学，在后段补西承重和安全返回路径。
3. 为东西承重分别设计独立的回桥，完成任意支路都会改变返回中庭的真实行走路线；不能只弹提示或把传送门改名。两支路可任意先后，不用一支路的教学作为另一支路的隐含前置。
4. 在独立试玩中先验证两种支路顺序、实地回桥与中庭中央桥门槛。正式存档接线放到后续完整章节集成；此阶段内存标记必须明确，不能宣称已持久化。
5. 每个高压遭遇后留休整，机关与法术不能同时封死唯一落脚点。提高难度依靠空间、选招与已学机制组合，不靠堆血、减前摇或取消反击窗口。

本任务交付应包含原生场景、两种顺序的真实输入路线、门两端/出生点检查、实际截图和更新后的状态记录。默认 6HP 与 5HP 无可选盾分别留证；自动通过不等于真人觉得合理、有趣或更难。

## 后续开发顺序

| 顺序 | 交付 | 验收重点 | 相关 skills |
|---|---|---|---|
| 0 | Mac 开发基线 | 导入/运行现有工程；适配启动与检查入口；记录 Mac 实测结果，不改玩法凑兼容 | `godot-gdscript` |
| 1 | 两支路、承重和回桥 | 先教学再组合，两种先后顺序、真实返回捷径、门两端一致 | `level-design`、`godot-tilemap`、`godot-nodes-scenes`、`godot-resources` |
| 2 | 静声藏室与钟庭之心 | 可选壁跃/二段跳/冲刺路线，失败回安全下层；唯一 +1 上限与一次回血，开返程口 | `platformer`、`level-design`、`save-systems` |
| 3 | 合鸣桥廊 | 两承重后开启；法师与铃翼组合，错开首次起手、可退让、不再叠鸣石；后段安全祭坛 | `game-ai`、`level-design`、`game-feel` |
| 4 | 终钟台与缚钟守望者 | 独立镰击/定点幽魂，先单招后组合；公平预警/反击、真实伤害/盾去重、固定单屏、失败重试 | `create-game-assets`、`godot-animation`、`godot-physics`、`game-ai` |
| 5 | 正式主线集成 | 第二关入口门槛、第三页地图/HUD、能力/奖励/桥/Boss/结局保存、跨章往返与旧档 | `save-systems`、`godot-signals-groups`、`godot-ui-control`、`game-ui-ux` |
| 6 | 整章回归与真人难度验收 | 两种支路顺序、可选路线、5HP 无盾主线；首次理解、失败原因、迷路/折返与第二关对比 | `level-design`、`game-design-theory` |

步骤 2 的奖励在独立试玩阶段明确为内存状态；步骤 5 完成后才能宣称永久奖励已进入主线。生命上限按奖励推导：基础 5 + 第一关生命花 1 + 第三关钟庭之心 1，收齐为 7；第二关水闸奖励不增加上限。主线不得强制领取可选生命或护盾。

Boss 原包选定为 `Bringer-Of-Death`，位于 Windows 的 `artifacts/downloads`，没有随 Git 提交；换机前另行携带完整原包及许可，正式导入只读核验动作、脚底/比例、来源/授权后登记 `assets/manifest.json`。现有法师和铃翼使用的正式资源已经入库，无需为运行试玩重新下载；增加原包未导入动作时才需要完整包。不要仅因原包已下载就视为 Boss 已开发或许可已完成发布审核。

## Mac 接手检查

```bash
git clone --branch fix/enemy-art-separation https://github.com/durex3/echoes-of-the-hollow.git
cd echoes-of-the-hollow
```

在 Godot 项目管理器导入 `project.godot`，先等资源导入完成，再分别运行主场景和第三关试玩场景。保留版本控制中的 `.uid` 和 `.import`，让目标机器重新生成被忽略的 `.godot` 缓存。

现有 `.cmd` 是 Windows 启动器。检查入口是 `tools/check.ps1`，需要 PowerShell、Python 和可执行的 Godot 路径；`tools/godot_path.ps1` 支持 `-GodotPath` 或 `GODOT_BIN`，但默认候选路径是 Windows 路径。Mac 适配必须确认实际 Godot 应用内可执行文件路径，以及当前脚本调用的 `python` 命令可用，不能把 Windows 全量通过当成 Mac 已验证。

如果新增 shell/Python 检查入口，必须与现有检查覆盖保持一致，包括法师真实反击扣血、三章 AI、壁跃、第三关默认/基线路线、前两章路线和跨进程存档；不能只测引擎能启动。玩家正式存档与测试档继续隔离；玩家存档、完整下载素材包、本机 skills 不会通过 Git 自动同步。

## 验证与保持项

玩法基线 `3ba389f` 在 Windows 完成 `tools/check.ps1 -Full -Visual`，结果见 [验证记录](verification.md)；Mac 实机验证尚未完成。本交接补充只有文档变化，未重新运行玩法回归。

- 每个行为变更运行 `tools/check.ps1`；共享移动/战斗、存档或章节流程加 `-Full`；视觉变化加 `-Visual` 并看实际截图。Mac 新入口要执行相同检查。
- 保留已认可的主角操作、两章地图与 Boss 身份、法师比例/技能、铃翼尖啸和踏壁辅助；只针对新增任务或可复现问题调整。
- 小怪连续受击仍正常扣血；反击必须在真实生效帧命中玩家，不能把玩家移动到有利位置凑测试。祭坛及 Boss 入口保存不回血。
- 不覆盖玩家存档，不重跑生成器覆盖手工房间，不提交缓存/测试截图/原始下载包，不修改桌面原素材。
- 内容开发优先；Windows 发布包、浏览器适配和发布验收仍在内容完成后推进。Mac 开发验证不等于 Mac 发布包验收。
